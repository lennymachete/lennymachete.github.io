Quote lines in. Finished documents out.

Two tools I built for my quoting team at Elemental Brands. Both take the lines already sitting in the quote and build the document people used to make by hand. Both are used daily across Quotes, Account Management, and Customer Support.

These are demos. Every product, code, and rule on this page is made up for the demo. No customer, pricing, or company data is here. The real tools hold none either. The tools themselves use no AI. I designed them and used AI to write the code.

Submittal Builder

A submittal is the packet a customer gets to approve what they are buying: one spec sheet per product, filled in and marked up to match the quote.

~20 minfor one line by hand, timed
156 pagesbuilt in about 10 minutes with the tool
82product templates, with an SOP
Need
Each line meant finding the right sheet, typing the ordering code into its boxes, and highlighting the matching rows. Long quotes took hours, so submittals only got made when someone asked.
Built
A browser tool. Paste the quote lines, add the current spec sheets, and it fills each sheet the way the team does by hand, then joins them into one PDF. Shared pages print once per product.
Check
It flags every place the quote and the spec sheet disagree. It never picks a product or changes a code. A person decides.
Result
Submittals went from a request to a habit. I now send one on every project.

Spec Diagram Builder

Lit panels are cut to size, so every order needs a drawing: dimensions, how an oversize panel splits, and where the wire leaves.

Need
Diagrams were drawn one at a time. No two looked the same, and splits were worked out by hand.
Built
Paste the quote rows and get a uniform diagram: panel size, even splits when a panel is over the limit, the wire exit, and a title block. It comes with an SOP.
Result
Every diagram is built the same way, whoever makes it.

How I built them

  1. Timed the hand process first

    One line, start to finish, about 20 minutes. That number is the reason the tool exists.

  2. Copied how the team already works

    The output matches what people made by hand. Nobody had to learn a new format.

  3. Kept data out

    No pricing, no customer names, no job data. Blank fields and sample rows only.

  4. Made it flag, not decide

    When the quote and the sheet disagree, it says so and stops. The person signs off.

  5. Wrote the SOP and handed it off

    Teammates tested it, I fixed what they found, and the SOP stays current with every change.
